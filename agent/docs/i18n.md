# 国际化（i18n）

polykit-agent 的界面文案支持多语言，内置简体中文（默认）和英文，运行时切换。

## 结构

```
apps/web/lib/i18n/
├── types.ts          # LocalePlugin { id, label, messages }、TranslationParams
├── registry.ts       # 语言注册表 + 浏览器语言匹配
├── format.ts         # translateMessage / 插值 / 相对时间格式化
├── messages/
│   ├── en.ts         # enLocale
│   └── zh-CN.ts      # zhCNLocale
└── registry.test.mjs # 注册表测试
```

- `registry.ts`：`registerLocale(plugin)` 注册语言（重复注册抛错），`getSupportedLocales()` 排序，默认 `zh-CN`，`resolveBrowserLocale()` 做浏览器语言匹配（存在 `pi-locale` 本地存储时优先）
- `format.ts`：`translateMessage` 三级回退——当前语言 → `en` → key 本身；dev 模式下缺失 key 会 warn。`{name}` 占位符插值；`formatRelativeTime` 用 `Intl.RelativeTimeFormat`
- React 侧 `hooks/useI18n.tsx` 提供 `I18nProvider`（读 `pi-locale`）与 `t(key, params)`；不在 Provider 内调用 `t` 会抛错

## 使用方式

```tsx
const { t } = useI18n();
return <div>{t("chat.placeholder")}</div>;
```

带参数：

```tsx
t("session.renamed", { name: "foo" })   // 文案里写 "已重命名为 {name}"
```

## 新增语言

1. 新建 `apps/web/lib/i18n/messages/<xx>.ts`，导出 `LocalePlugin`（`id`、`label`、`messages`），消息对象以 `en.ts` 为模板逐键翻译
2. 在 `apps/web/lib/i18n/registry.ts` 里 `import` 并 `registerLocale(...)` 注册
3. 同步扩展 `Locale` 类型联合（`types.ts`）——不扩展会类型报错，这就是「忘记注册」的编译期保险
4. 顶部栏语言切换器会自动出现新语言

## 注意事项

- **服务端文案不需要 i18n**：这个机制只服务前端 React 组件；API 错误消息仍是英文
- 保持 key 扁平、语义化（按组件/领域分组），不要在文案里拼 HTML
- 新增 key 时 `en.ts` 和 `zh-CN.ts` 都要加，否则 dev 下会有缺失告警，且回退到英文
