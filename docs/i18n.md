# Internationalization

PolyKit localizes presentation, not machine contracts.

The goal of a Chinese UI is consistent Chinese product copy, not the removal of every English technical term. Identifiers and ecosystem-facing values must remain stable so workflows, documentation, bug reports, configs, and model APIs still refer to the same thing.

## Core rule

**Translate concepts, not identifiers.**

### Translate

- buttons, menus, dialogs, status text, empty states and other product copy;
- parameter labels and tooltips;
- human-readable option labels;
- node names and descriptions when a node pack supplies a locale;
- ordinary concepts such as `Texture Resolution` → `纹理分辨率`.

### Do not translate

- node-pack ids and node ids;
- `class_type`;
- parameter ids such as `texture_resolution`;
- enum/config values such as `1024_cascade`;
- quantization values such as `Q5_K_M`;
- filenames, paths and API fields;
- well-known technical names when translating them would make ecosystem lookup harder, such as `GGUF`, `SLaT`, `VRAM`, `CUDA`, `UV`, `GLB`, `Seed`, or `Guidance` when appropriate.

For example, a Chinese control may display `GGUF 量化` while the submitted value remains exactly `Q5_K_M`.

## Application UI

`src/shared/i18n.ts` uses English (`en-US`) as the source locale. `TranslationKey` is derived from the English dictionary, and the Chinese dictionary must satisfy the full key set at compile time.

This means adding a core UI string requires both source copy and a Chinese translation; missing Chinese keys are TypeScript errors instead of runtime English/Chinese mixtures.

## Node-pack UI

Node packs own their model-specific presentation strings. The core application must not accumulate translations for every third-party model.

English source fields remain required and act as the fallback. A node pack can add an optional `i18n` object beside a display field.

### Parameter example

```json
{
  "id": "gguf_quant",
  "label": "GGUF Quantization",
  "type": "select",
  "default": "Q5_K_M",
  "tooltip": "GGUF quantization level. Less VRAM = slightly less accurate.",
  "i18n": {
    "zh-CN": {
      "label": "GGUF 量化",
      "tooltip": "GGUF 量化等级。较低量化通常占用更少 VRAM，但精度可能略有下降。"
    }
  },
  "options": [
    { "value": "Q5_K_M", "label": "Q5_K_M" }
  ]
}
```

Only `label` and `tooltip` change with locale. `id`, `default`, option `value`, validation bounds, and conditional logic remain single-source machine values.

### Option example

```json
{
  "value": "1024_cascade",
  "label": "High (1024 cascade)",
  "i18n": {
    "zh-CN": {
      "label": "高质量（1024 Cascade）"
    }
  }
}
```

The UI displays the localized label while the executor still receives `1024_cascade`.

### Node example

```json
{
  "id": "generate",
  "name": "Generate Mesh",
  "i18n": {
    "zh-CN": {
      "name": "生成网格"
    }
  }
}
```

Node locales may also provide `description` and `inputLabels`. Pack-level locales may provide `name` and `description`.

## Fallback order

For node-pack presentation:

1. requested locale, for example `zh-CN`;
2. the English/source field already present in the manifest.

A node pack therefore remains fully usable without any translations, and adding a locale never changes execution behavior.
